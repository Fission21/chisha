# 技术方案

## 1. 架构

```
[Next.js 前端]  ←→  [FastAPI 后端]  ←→  [SQLite / Postgres]
                     (营养计算 / 推荐 / 菜谱 API)   (foods / recipes / users)
                     [数据管道：Python 脚本导入 食物成分表 + 菜谱]
```

## 2. 技术栈（推荐）

- 前端：Next.js + TypeScript + Tailwind CSS（SEO 好、易部署、生态成熟）
- 后端：FastAPI（Python）——营养计算、推荐逻辑，未来接 LLM 方便
- 数据库：SQLite（MVP，零运维）→ 后续 PostgreSQL
- 数据管道：Python（pandas）导入清洗 食物成分表 JSON + 菜谱
- 部署：前端 Vercel / 静态托管，后端容器化

> 备选：纯 Next.js 全栈（API Routes + better-sqlite3），减少语言栈。推荐保留 Python 后端，因为数据管道与推荐 / AI 生态更好。

## 3. 推荐算法（MVP：规则打分）

```
score(recipe, user) =
  w1 × 营养匹配度（这道菜的营养 vs 用户餐次目标）
  + w2 × 目标标签匹配（高蛋白 / 低碳水 / 低脂 ...）
  + w3 × 偏好匹配（忌口硬排除，偏好加权）
  + w4 × 多样性（避免连续重复）
```

- 先硬性过滤：忌口、过敏、超出餐次热量过多
- 再打分排序，按早 / 午 / 晚 / 加餐各出 Top 3~5

## 4. API 设计（草案）

```
POST /api/users/onboarding        # 提交身体档案 → 返回每日目标 + 初始推荐
GET  /api/me/daily-target         # 每日热量 / 宏量营养素
GET  /api/recommendations?meal=breakfast&goal=cut
GET  /api/recipes/{id}            # 菜谱详情
GET  /api/foods?q=鸡胸肉          # 食材营养查询
```
