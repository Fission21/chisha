# ADR-0007：可配置的演示账户初始化

- 状态：已采纳
- 日期：2026-08-05
- 决策人：项目作者（CC）
- 标签：#认证 #安全 #部署 #开发体验
- 关键词：DEFAULT_ACCOUNT_EMAIL、DEFAULT_ACCOUNT_PASSWORD、seed、演示账户

## 1. 背景

项目已有注册和登录功能，但首次启动不会创建用户。若在 README 或代码中提交固定账号和明文密码，公开 Render 部署上的所有访问者会共用同一份档案、收藏和饮食记录；单令牌模型还会让他们相互下线。这也违反了密码不得提交或写入日志的约束。

本地演示登录流程仍需要一个可重复创建的账户，因此需要一个不把密码放进仓库、又不改写已有用户数据的初始化方式。

## 2. 目标与边界

### 目标

- 让本地或受控演示环境可以在首次 seed 时预置一个可登录账户。
- 密码只从运行时环境变量读取，数据库只保存既有 PBKDF2 哈希和 salt。
- 重复启动保持幂等，绝不重置现有用户的密码、令牌或同步数据。

### 不在本次范围内

- 不提供公开共享账户、管理员账户或权限分级。
- 不为现有账户实现密码重置、令牌刷新或多设备会话。
- 不在 Render 等公开部署中预配置演示凭据。

## 3. 候选方案

### 方案 A：在 README 和代码中固定账号及明文密码

- 优点：开箱即用。
- 缺点：所有公开部署访问者共享可写账户；密码会进入版本历史。
- 风险：用户健康档案泄露、会话相互覆盖、部署者误把演示密码用于真实环境。

### 方案 B：通过环境变量可选创建账户

- 优点：不提交密码；部署者自行控制是否启用；可复用现有密码哈希与登录流程。
- 缺点：首次部署需额外设置两个变量。
- 风险：配置不完整会导致启动失败，需要明确错误提示和文档。

### 方案 C：只要求用户手动注册

- 优点：无需新增初始化逻辑。
- 缺点：不能满足可重复的受控演示账户需求。

## 4. 最终决策

选择方案 B。

1. 只有同时设置 `DEFAULT_ACCOUNT_EMAIL` 和 `DEFAULT_ACCOUNT_PASSWORD` 时，`app.seed` 才会创建账户。
2. 两项未设置时不创建用户；只设置一项时启动失败，避免误以为凭据已生效。
3. 若邮箱已存在，seed 不修改密码哈希、令牌、档案、收藏或日记。
4. Docker Compose 仅转发宿主机或未提交 `.env` 中的变量；README 只说明交互式设置方式，不给出固定明文密码。

不选择方案 A，因为该项目公开说明了 Render 部署入口，固定可写凭据不是零风险。方案 C 保留给不需要演示账户的部署，但不能单独满足本需求。

## 5. 架构与实现约束

- `api/app/default_account.py` 是唯一的账户 seed 入口，必须复用 `RegisterIn` 的邮箱/密码校验和 `hash_password()`。
- 密码不得写入日志、响应、README、`.env.example` 或版本控制；`.env.example` 只能包含安全占位符。
- seed 必须在同一事务中创建新用户，且对已有用户只读。
- Compose 不得给变量提供仓库内默认值；公开部署保持未配置状态。
- 登录及用户数据 API 继续使用 ADR-0004 的 Bearer 认证边界，不为演示账户增加绕过路径。

## 7. 验收标准

- 未设置变量时不创建账户；只设置一项时明确拒绝启动。
- 有效配置首次 seed 后可通过现有 `/api/auth/login` 登录，数据库不保存明文密码。
- 再次 seed 不新增同邮箱用户，也不改写密码哈希或令牌。
- `docker compose config --quiet` 与认证定向测试/等价临时 SQLite 验证通过。

## 8. 后果与风险

### 正面影响

- 受控演示可以复现登录流程，无需把真实或固定密码提交到仓库。
- 现有用户数据和认证协议保持不变。

### 负面影响和代价

- 部署者需要保管自己的环境变量。
- 若首次账户已经创建，单纯修改环境变量不会重置密码；需走未来明确设计的密码重置流程。

### 持续跟踪风险

- [ ] 若公开演示需要免注册体验，评估独立的匿名只读样例数据，而不是共享可写账户。
- [ ] 在用户规模增长后，结合 ADR-0004 评估令牌过期、限流和密码重置。

## 9. 复盘

- 预期目标是否达成：已通过临时 SQLite 验证首次创建、重复 seed 与登录。
- 实际收益和成本：新增一个小型 seed 辅助模块和配置说明，无新依赖。
- 哪些假设被证明错误：公开开源并不意味着共享可写账户没有风险。
- 是否需要新建 ADR 替代当前决策：若增加匿名演示模式、密码重置或共享数据隔离，则新建 ADR。
