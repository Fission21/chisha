# ADR-0008：健身健康画像与厨具可用性筛选

- 状态：已采纳
- 日期：2026-08-06
- 决策人：项目作者（CC）
- 标签：#营养 #推荐 #健康筛选 #厨具 #用户体验
- 关键词：均衡健身、严格控油控盐、添加油、钠、蛋白质密度、可用厨具

## 1. 背景

菜谱库已经覆盖 238 道菜，但“健身餐”不能只靠标题和标签判断。用户真正关心的是：

1. 我手上的厨具能不能做这道菜；
2. 这道菜每份的热量、蛋白质、脂肪、钠和添加油是多少；
3. 减脂、增肌和日常均衡饮食的筛选标准是否不同；
4. 过敏原、加工肉、深炸和高钠调味是否被明确处理。

此前标签同时混合了来源、菜系、食材和健康描述，推荐也主要使用热量、蛋白质和标签，不能作为严格健康筛选的唯一依据。

## 2. 参考原则

- ISSN《Protein and Exercise》：运动人群每日蛋白质可按 1.4-2.0 g/kg 作为一般参考；单次约 20-40g，并尽量分散摄入。
- Academy / Dietitians of Canada / ACSM《Nutrition and Athletic Performance》：运动表现和恢复同时取决于食物类型、数量、时机和个体情况，不用单一宏量营养素替代个体化方案。
- WHO《Healthy diet》：健康饮食的基础是充足、平衡、适度和多样；优先未精制碳水、蔬果、豆类和多样蛋白，限制不健康脂肪、游离糖和钠。
- WHO 钠建议：成人每日钠低于 2000mg，约等于食盐低于 5g。
- Harvard Healthy Eating Plate：以半盘蔬果、四分之一全谷物、四分之一优质蛋白和适量健康油作为可解释的餐盘参考，不把它当作固定热量处方。

## 3. 决策

### 3.1 两种饮食模式

- `balanced`：均衡健身。热量和蛋白质匹配目标，同时用健康评分、脂肪、钠、纤维和加工方式排序，不强制把所有脂肪降为零。
- `strict`：严格控油控盐。只允许构建期判定为 `strictEligible` 的菜谱；这是产品筛选规则，不是医疗安全证明。

严格模式的默认每份条件为：

- 添加油不超过 10g；
- 添加糖不超过 12g；
- 总脂肪不超过 20g；
- 钠不超过 700mg；
- 蛋白质不少于 10g；
- 排除深炸和加工肉。

这些是产品默认阈值，不替代用户的医生或注册营养师建议。主餐、加餐和运动量差异较大时，后续可以增加按餐次配置的阈值。

### 3.2 构建期健康画像

`scripts/build_data.py` 为每道菜生成 `health` 对象，包含：

- `score`：用于排序的估算评分；
- `strictEligible`：是否进入严格模式；
- `addedOilG`、`addedSugarG`：按每份估算；
- `proteinDensity`：每 100 kcal 的蛋白质克数；
- `deepFried`、`processedMeat`：做法与食材风险标记；
- `labels`：高蛋白、低油、低钠、低脂、控糖、高纤维等解释标签；
- `confidence`：当前为 `estimated`。

炸油的烹饪投入量不等于实际摄入量。源菜谱可以记录宽油，但营养计算应使用实际吸收量估算并在食材备注中说明，避免把整锅炸油计入一份菜。

### 3.3 厨具语义

菜谱的 `equipment` 表示完成该菜谱所需的厨具集合，统一词表包括平底锅、炒锅、汤锅、蒸锅、烤箱、空气炸锅、微波炉、电饭煲、搅拌机、冰箱和无需加热。

筛选支持：

- `any`：菜谱包含所选任一厨具；
- `all`：菜谱包含所选全部厨具；
- `available`：菜谱所需厨具必须是用户已拥有厨具的子集。

用户页面默认使用 `available`，因为“我有这些能做什么”比“菜谱恰好包含某个工具”更符合使用场景。

### 3.4 过敏原

构建阶段合并源数据声明和食材名称推导的标准过敏原；运行期使用同义组匹配，例如牛奶/乳制品、虾/贝类。空数组不再被产品文案解释为绝对安全，页面继续保留估算和来源提示。

## 4. API 与界面边界

- 菜谱列表支持健康模式、健康标签、排除过敏原、最大热量、最小蛋白、最大脂肪、最大钠、最小纤维和最大添加油。
- 菜谱列表支持厨具多选和三种厨具逻辑。
- 普通计划、周计划、换菜和目标热量菜谱都接受 `health_profile`，严格模式不从不合格候选中兜底推荐。
- 菜谱卡片和详情页展示健康画像的解释字段，而不是只显示“健康”二字。

## 5. 验收标准

- 空气炸锅菜谱能在器材 facets 和“我有的厨具”筛选中出现。
- 严格模式返回的每道菜均满足构建期 `strictEligible`，且 API 可验证油、钠和脂肪阈值。
- 用户选择多种厨具后，`available` 模式不会返回需要未选择厨具的菜谱。
- 过敏原筛选能处理标准同义组，不把空数组当作安全保证。
- 目标热量生成、普通计划和周计划均能使用严格模式。
- 前端桌面、390px 窄屏、筛选清空、热量生成和菜谱新标签页跳转完成浏览器验证。

## 6. 风险与后续

- 中国菜的油、盐和酱料吸收量存在估算误差，必须保留说明，不表达为医疗结论。
- 当前食物表没有完整的饱和脂肪、反式脂肪和添加糖字段；严格模式先使用可审计的食材/营养近似，后续再补充更细营养数据。
- 运动前后碳水需要按训练量和项目进一步细分，不能用“低碳水”作为所有减脂用户的统一目标。
